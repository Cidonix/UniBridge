# Profiler capture and bottom-up qualification

All Windows commands and child launches require an Administrator shell. This suite does not launch Unity or edit authored scenes. Native fixture import/cleanup and Editor readiness are controlled by the calling task.

`run_profiler_extensions_regression.py --repo <checkout> --overlay <candidate> --prior-overlay <earlier-candidate> --step 2|3 --newtonsoft <dll> --unity-core <real-CoreModule.dll> --report <fresh.json>` compiles exact production helpers, tool producers, closed action output rules, typed parameters, math serializers and the extracted actual policy branch. File operations are real, while the native profiler backend and copied frame source are explicit deterministic fixtures. Source and fixture hashes are recorded. Step 2 covers preserve/load/restore, invalid load rollback, changed bytes/flags, durable same-process reconstruction, process/root/path/hash guards, missing baseline save, wrong/active leases, canceled admission, strict schema and exclusive scheduler selection. Step 3 adds repeated calls, recursive interval union, GC event attribution once per logical ancestry group, separate physical frames/UInt64 threads/marker categories, unknown coverage, cancellation, deadlines, top-N and work bounds, exact producer projection and play-mode precondition.

Import only `Native/UniBridgeProfilerExtensionsFixture.cs` into a fresh owned Editor fixture folder in the test project. Execute `Tools/UniBridge Validation/Profiler Extensions/PrepareKnownCapture`. It preserves the original buffer and four relevant recording flags, records nested repeated markers over 25 Editor ticks, verifies stopped `SaveProfile` bytes are stable, saves a known `.data` and an invalid file, restores the original buffer/flags, then writes a fresh `Library/AgentValidation/ProfilerExtensions-<uuid>/native-input.json`. A native PASS requires x64 Mono Unity 6.6 and actual saved capture creation; deterministic fixtures are not a substitute.

Run `run_profiler_extensions_wire.py --repo <checkout> --relay <current-production-relay> --project <exact-test-project> --inputs <native-input.json> --step 2|3 --validator-path <compatible-jsonschema-directory> --report <fresh.json>`. The driver requires a Python-compatible `jsonschema` installation (`--validator-path` is optional when it is already installed); it negotiates MCP `2025-11-25` and independently validates the registered outputSchema, raw structuredContent and text projection for every profiler response. It uses the bundled ordinary MCP client, checks project identity and input bytes, exercises expected errors, one explicit load and one explicit restore. Step 2 additionally executes a real invalid native load with rollback. `--domain-reload` requests actual compilation through the imported menu and waits for before/after reload receipts in the same Editor process, then retries only the read-only `WaitForReadyAfterReload` checkpoint for up to 120 seconds until nested readiness and compilation health are confirmed before reading the durable lease. Step 3 compares actual recorded repeated-marker calls/self time and recursive union to physical sample data; aggregate IDs are rejected as physical callstack selectors. Scouting starts with one latest frame without raw arrays, with at most 12 metadata-only fallback frames using actual source-selected IDs; full physical controls read only one matching thread/frame. Cleanup restores the exact owned lease once and retains all failure evidence. A positively acknowledged LoadCapture is registered for cleanup after exact root/path/hash/lease identity checks before independent wire/schema validation, so a schema mismatch still fails the gate while the owned mutation can be restored.

LoadCapture requires project-relative `.data`, exact CaptureSha256 and ExpectedProjectRoot. It creates one durable lease under `Library/UniBridge/ProfilerCaptures`. The requested file and original stopped buffer are retained with exact file-integrity hashes. Before replacing the buffer, the original backup is explicitly loaded once and its two equal stopped SaveProfile hashes qualify originalLoadedSha256; native .data load may canonicalize file headers. Restoration compares the full saved loaded-buffer representation against this qualified canonical hash, never against the original backup file hash. An already qualified mismatch is never rebaselined. RestoreCapture requires the exact lease ID and expected root; edited current bytes or flags block restoration. The four restored flags are enabled, profileEditor, allocation callstacks and memoryRecordMode. A new Editor process cannot claim the prior lease. An interrupted/uncertain native transaction remains explicitly recovery-required; it never silently overwrites a buffer. Reads never implicitly load, clear or enable captures. Once the exclusive transaction starts, request cancellation is deferred by the existing scheduler so the actual result is retained in command recovery.

RecordedBottomUp is a separate read action. Existing six actions and defaults retain their behavior. Logical group IDs are response-local aggregate identities; physical sample IDs remain drilldown identities. Inclusive time is a same-group interval union independently per physical frame/thread, self time sums physical exclusive time, and each GC event is counted once per distinct ancestor group. Caller groups can share an allocation and must not be summed globally. Unknown/incomplete coverage stays null/partial. The request shares extraction/aggregation timeout and cancellation, up to 60 frames/100000 raw samples, 512 accumulated groups and 300 returned groups; sample ID examples are bounded to eight.

No CoreCLR/Unity 7 or native Mono crash qualification is included.
